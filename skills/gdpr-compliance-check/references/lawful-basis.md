# 合法性基础决策树与 Art.9 例外事由

## 一、Art.6 六选一（普通个人数据）

按顺序往下问，命中即停。

| # | 基础 | 条款 | 典型场景 | 关键约束 |
|---|---|---|---|---|
| 1 | 同意 consent | 6(1)(a) | 营销邮件、非必要 Cookie、可选功能 | 可撤回（7(3)）；不得捆绑；需可举证 |
| 2 | 履行合同 contract | 6(1)(b) | 下单发货、账号注册、售后 | 必须是「履行合同所必需」，不是「对业务方便」 |
| 3 | 法律义务 legal obligation | 6(1)(c) | 税务留存、反洗钱、配合执法 | 需指向具体的欧盟或成员国法律 |
| 4 | 重大利益 vital interests | 6(1)(d) | 医疗急救、生命危险 | 极窄，不能用于常规业务 |
| 5 | 公共任务 public task | 6(1)(e) | 公共机构履职 | 需法律授权 |
| 6 | 正当利益 legitimate interests | 6(1)(f) | 反欺诈、网络安全、内部管理 | **必须做 LIA 平衡测试**；数据主体可反对（21） |

### LIA 平衡测试三步（选正当利益时必做）

1. **目的检验**：追求的利益是否正当、清晰、现实？
2. **必要性检验**：处理是否必要？有无侵入性更小的方式？
3. **平衡检验**：该利益是否压过数据主体的权益与合理预期？
   - 数据性质（是否敏感）、处理方式、数据主体合理预期、
   弱势群体（儿童/员工）、是否超出其预期

> 结论必须书面留档，否则 Art.5(2) 问责义务无法举证。

## 二、Art.9 特殊类别数据（原则禁止）

**范围**：种族/民族、政治观点、宗教或哲学信仰、工会成员身份、
基因数据、用于唯一识别的生物识别数据、健康数据、
性生活或性取向数据。

处理前提：**先有一条 Art.6 基础，再有一条 Art.9(2) 例外**，两条缺一不可。

| Art.9(2) 例外 | 说明 |
|---|---|
| (a) 明示同意 | 需 explicit consent，比一般同意门槛更高；成员国可禁止 |
| (b) 就业/社保法下的义务或权利 | 需法律或集体协议授权 |
| (c) 数据主体无法表达同意时的重大利益 | 如急救 |
| (d) 非营利机构正当活动 | 仅限其内部目的 |
| (e) 数据主体自行公开的数据 | |
| (f) 法律主张的确立、行使或抗辩 | 诉讼等 |
| (g) 重大公共利益 | 需法律授权，且有适当保障 |
| (h) 医疗/职业健康目的 | 由专业人员或承担保密义务者处理 |
| (i) 公共卫生领域的公共利益 | 如传染病防控 |
| (j) 归档/科研/历史研究/统计目的 | 需符合 Art.89(1) 的保障措施 |

**判断口诀**：拿不出 Art.9(2) 的具体条款 → 立即停止处理并删除。

### 犯罪记录数据（Art.10）

比 Art.9 更严：仅在**官方机关控制**下，或**欧盟/成员国法律授权**时处理。
业务自查里发现此类数据，直接标 P0。

## 三、同意的有效性（Art.4(11) + Art.7）

| 要求 | 常见误区 |
|---|---|
| 自由作出 | 「不同意就不能用」的捆绑同意无效 |
| 具体 | 一揽子同意无效 |
| 知情 | 未告知目的/接收方 |
| 明确 | 「继续使用即视为同意」无效 |
| 可举证 | 没有时间戳记录 = 无法证明 |
| 可撤回 | 未提供撤回通道或撤回比授予更难 |

**同意记录必须存**：时间戳、告知文本版本、同意范围、撤回时间。
表结构见 `assets/consent-record-schema.md`。

## 四、儿童（Art.8）

- 信息社会服务（如 App、网站）面向儿童，且依赖同意处理时：
  - **默认 16 岁**为同意年龄门槛
  - 成员国可下调，但**不得低于 13 岁**
- 未满门槛 → 需取得监护人的同意或授权
- 需采取合理努力验证监护人身份（考虑技术可行性）
- 告知文本必须用儿童能理解的语言

## 五、常见场景 → 合法性基础映射

| 场景 | 建议基础 | 备注 |
|---|---|---|
| 订单履约、物流配送 | 合同 | 必需 |
| 交易记录留存（税务） | 法律义务 | 通常 7-10 年 |
| 营销邮件 / 短信 | 同意 | 需可撤回；B2C 尤甚 |
| 非必要 Cookie / 广告追踪 | 同意 | ePrivacy 要求事前同意 |
| 站点安全、反欺诈 | 正当利益 | 补 LIA |
| 产品改进统计分析 | 同意 或 正当利益 | 有追踪性质建议用同意 |
| AI / 模型训练 | 同意 或 正当利益 | 高风险建议 DPIA |
| 人脸识别门禁 | 明示同意 或 重大公共利益 | Art.9 生物识别，务必 DPIA |
| 员工考勤管理 | 合同 / 法律义务 | 员工属弱势数据主体，需更谨慎 |
