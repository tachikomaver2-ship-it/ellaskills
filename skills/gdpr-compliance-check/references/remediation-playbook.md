# GDPR 整改手册

按优先级给动作。P0 是「不马上做就可能出事」，P2 是「做了更稳」。

## P0 — 7 天内

| 情形 | 动作 | 依据 |
|---|---|---|
| 处理 Art.9 敏感数据但无例外事由 | 立即停止处理，隔离存储，评估是否删除 | 9(1) |
| 明文存储密码 / API Key | 改为加盐哈希（bcrypt/argon2）；密钥移入 KMS；清理日志 | 32 |
| 收集身份证号 / 社保号但无必要 | 停止收集，用内部替代 ID；存量做假名化或删除 | 87 / 5(1)(c) |
| 跨境传输无合法机制 | 暂停传输，或签署 SCCs + 完成 TIA | 44-49 |
| 与处理者共享但未签 DPA | 补签符合 Art.28(3) 的 DPA | 28 |
| 无泄露响应机制 | 建立 72 小时响应流程与泄露登记册 | 33(5) |

## P1 — 30 天内

| 情形 | 动作 | 依据 |
|---|---|---|
| 合法性基础未明确 | 逐处理活动落实到 Art.6 具体条款并留档 | 6 |
| 依赖正当利益但无 LIA | 补做三步平衡测试并书面留档 | 6(1)(f) |
| 无留存期限 | 按数据类别定义期限与起算点，写入隐私政策 | 5(1)(e) |
| 留存到期未实际删除 | 实现硬删除或不可逆匿名化，保留删除日志 | 17 |
| 未做最小化评估 | 逐字段评审「删掉它目的还能否达成」 | 5(1)(c) |
| 无静态加密 / 无访问控制 | 启用加密，按角色最小授权，敏感访问留审计日志 | 32 |
| 无 DSAR 流程 | 建立受理渠道、责任人、身份验证与 1 个月 SLA | 12(3) |
| 隐私政策缺失要素 | 用 `docs_check.py` 定位缺失项并补齐 | 13/14 |
| 无 ROPA | 用 `assess.py --ropa` 生成草稿并按实际填充 | 30 |
| 无欧盟机构且无欧盟代表 | 指定 Art.27 代表并公布联系方式 | 27 |

## P2 — 90 天内

| 情形 | 动作 | 依据 |
|---|---|---|
| 高风险处理未做 DPIA | 按 EDPB 九项标准评估，命中 2 项以上即做 | 35(3) |
| 未评估是否需要 DPO | 按三类强制情形判断，或至少指定负责人 | 37 |
| 自动化决策无人工介入 | 增加人工复核、异议与逻辑说明通道 | 22 |
| 敏感字段未假名化 | 对标识符做令牌化/加密，降低泄露后可识别性 | 32(1)(a) |
| 员工未培训 | 对接触个人数据的岗位做年度培训并留记录 | 39(1)(b) |
| 备份恢复未验证 | 定期演练恢复并留记录 | 32(1)(c) |

## 数据主体权利响应流程（DSAR）

| 步骤 | 动作 | 时限 |
|---|---|---|
| 1 受理 | 记录请求人、请求类型、接收渠道 | Day 0 |
| 2 身份验证 | 用已有账号体系验证；**不得借此过度收集新证件** | Day 0-3 |
| 3 定位数据 | 按 ROPA 与数据清单检索全系统（含备份、日志、第三方） | Day 3-10 |
| 4 法益权衡 | 删除权/可携权是否有例外（如法律义务留存） | Day 10-15 |
| 5 执行 | 导出 / 更正 / 删除 / 限制，并同步至处理者 | Day 15-25 |
| 6 回复 | 书面告知处理结果；拒绝需说明理由与救济途径 | **≤ 1 个月** |
| 7 延期 | 复杂请求最多延 2 个月，须在首月内告知理由 | ≤ 3 个月 |

**拒绝必须给出理由**：不回复、拖过 1 个月本身就是违规（Art.12(3)）。

## 数据泄露响应（Art.33/34）

| 阶段 | 动作 | 时限 |
|---|---|---|
| 发现 | 记录发现时间、发现人、初步范围 | T0 |
| 评估 | 判断是否对个人权益造成风险；是否高风险 | T0 → 尽快 |
| 遏制 | 隔离系统、吊销凭据、封堵入口 | 立即 |
| 通知监管机构 | 即使信息不全也应先报，可补充提供 | **≤ 72 小时** |
| 通知数据主体 | 高风险时，用清晰平实语言说明 | 不得无故延迟 |
| 登记 | 无论是否上报，都记入泄露登记册 | 持续 |
| 复盘 | 根因分析 + 整改措施闭环 | 事后 |

**72 小时从「知悉」起算**，不是从「发生」起算；拿不准就先报，
迟报本身是独立违规项。

## 数据最小化：字段评审三问

对每个字段依次问：

1. **没有它，目的还能达成吗？** 能 → 删掉
2. **能用更粗粒度替代吗？** 精确生日 → 年龄段；GPS → 城市
3. **能缩短留存吗？** 一次性用途 → 用后即删

## 跨境传输机制选择

```
是否传输出 EEA？
├─ 否 → 无需机制
└─ 是 → 目的国是否有充分性认定？
       ├─ 是 → Art.45，直接传输（仍需记录）
       └─ 否 → 是集团内部？
              ├─ 是 → BCRs（Art.47，需监管批准）
              └─ 否 → SCCs（Art.46(2)(c)）
                     └─ 必须做 TIA + 补充措施（Schrems II）
```
